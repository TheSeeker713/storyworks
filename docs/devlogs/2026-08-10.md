# Storyworks devlog — 2026-08-10

## 13:58 — Private Journal safety gate

The audit was right: the crypto engine was real, but the product promise was not. Password and
recovery-key unwrapping work in the backend, and Keychain helpers were already called, but the
unlock dialog only offered a password. Touch ID did not exist at all.

I did not pretend a web-only patch could finish and prove Touch ID under the no-browser/no-live
process rule. New Private Books are now disabled in both UI and API with direct copy explaining
why. Existing encrypted Books keep three recovery choices in the unlock dialog: Keychain,
password, or recovery key. The Keychain path sends no password so the backend actually performs
its stored-credential lookup. Touch ID is called out as unavailable rather than implied.

Proof used only throwaway vaults: Journal crypto + safety-gate tests `4 passed`; Next production
build green; TypeScript/lint green. Commit `82c2aba` pushed to `main`.

Open security item: real Touch ID needs a native macOS `LocalAuthentication` path and a human
runtime walk. Until that exists and is proven, new Private Books stay off.

## 14:17 — Notes type inference

The old path was exactly as narrow as the audit said: a hashtag regex followed by
`ensure_stub(... type_="character")`.

Notes now detect explicit typed tags and ordinary capitalized mentions, then infer Character,
Prop, Scene, or Worldbuilding from the containing sentence. Sentence boundaries matter here:
nearby entities no longer vote on each other. Typed forms such as `#prop:Black-Key` remain a
deterministic escape hatch, but normal prose is handled too. Typed Codex links are persisted back
into note frontmatter and every new entity still becomes a silent stub with no confirmation.

Tests cover all four types in ordinary prose, all four typed overrides, API persistence, and
actual Codex stub types. Full suite `46 passed`; build and TypeScript/lint green. Commit `4447655`
pushed.

## 14:44 — Rename and dated identities

Projects, Draft documents, module content, and Codex entries all have visible rename controls now.

## 14:56 — Paragraph timestamps

Notes and Journal now use a real TipTap paragraph attribute, not a document timestamp painted next
to every line. A paragraph without `createdAt` gets an ISO timestamp in the same transaction that
creates it; `keepOnSplit: false` makes each Enter-created paragraph earn its own time. The editor
renders a local-time label from that value.

The ordered timestamps persist in Markdown frontmatter and reload into the corresponding
paragraphs. The autosave single-flight queue now carries body + timestamp array as one payload,
so a newer body cannot be paired with an older timestamp list. Old callers that omit the field do
not erase existing timestamps.

Backend tests cover independent Note/Journal timestamps and legacy-write preservation. Full suite
`53 passed`; build and TypeScript/lint green. Commit `a009f0a` pushed. The actual Enter interaction
still needs Jeremy’s browser walk; no agent-originated live claim.
