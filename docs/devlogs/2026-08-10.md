# Storyworks devlog — 2026-08-10

## 13:58 — Private Journal safety gate

The audit was right: the crypto engine was real, but the product promise was not. Password and
recovery-key unwrapping work in the backend, and Keychain helpers were already called, but the
unlock dialog only offered a password. Touch ID did not exist at all.

I did not pretend a web-only patch could finish and prove Touch ID under the no-browser/no-live
process rule. New Private Books are now disabled in both UI and API with direct copy explaining
why. Existing encrypted Books keep three recovery choices in the unlock dialog: Keychain,
password, or recovery key. The Keychain path sends no password so the backend actually performs
its stored-credential lookup. Touch ID is called out as unavailable rather than implied.

Proof used only throwaway vaults: Journal crypto + safety-gate tests `4 passed`; Next production
build green; TypeScript/lint green. Commit `82c2aba` pushed to `main`.

Open security item: real Touch ID needs a native macOS `LocalAuthentication` path and a human
runtime walk. Until that exists and is proven, new Private Books stay off.
