# Storyworks devlog — 2026-08-11

## 20:37 — PDF export tests skip cleanly without macOS fonts

The PDF exporter intentionally depends on one of three macOS system fonts, but the three tests
that exercise PDF generation tried to run everywhere. That made collection portable and execution
machine-dependent in the worst way: a machine without Arial Unicode, Arial, or SFNS could only
hard-fail inside `_as_pdf`.

I matched the existing STT test pattern. Font availability is evaluated once during collection,
and each PDF-dependent test now has an explicit `pytest.mark.skipif` with a direct reason. The
Markdown and FDX-only tests remain unconditional, so missing fonts do not hide unrelated export
regressions.

The requested verbose proof was `5 passed in 0.77s` on this Mac, with all five test names reported
as `PASSED`. The full suite then finished at `53 passed in 7.28s`. No test assertions or exporter
behavior changed.

## 20:39 — Journal callbacks now come from the actual journal

Journal had no memory at all. I added a local memory pass over the current Book's markdown entries.
It prefers a matching month and day from a prior year for On This Day, then falls back to the most
recent earlier entry when there is no anniversary. Empty entries, future entries, another Book's
entries, and encrypted ciphertext are not candidates.

The follow-up is built around a real sentence taken from the selected entry. The card prints that
sentence as a quote and puts the same words into the question, so the UI cannot claim a callback
without showing what grounded it. Anniversary callbacks also say how many years ago the entry was
written. Both normal Journal mode and its default Zen surface show the card beside the current
entry.

Two focused tests use throwaway vaults. One proves an older anniversary beats yesterday's newer
entry and checks the exact lighthouse sentence in the generated question. The API test proves the
recent-entry fallback and checks that the ferry-horn sentence survives into the question. Focused
result: `2 passed in 0.32s`. Full suite: `55 passed in 6.96s`. The Next production build compiled,
ran TypeScript, and generated all four static pages successfully.

## 20:43 — Journal streaks and local entry metadata

Every Journal save now carries its own local date, local time with UTC offset, and word count in
the markdown frontmatter. The first save fixes date and time; later edits preserve both and update
only the count. Plaintext counts are recomputed by the backend from the actual body. An encrypted
entry accepts the count computed from plaintext in the editor before sealing, so ciphertext never
turns into a fake one-word entry.

The new stats pass reads one Book at a time and computes entry count, total words, and a streak
from distinct calendar days. A streak may end today or yesterday, which means opening the app
before writing today does not erase yesterday's run. Both Zen and normal Journal chrome now show
the count and streak. The current entry also shows its logged date, time, and words.

The first full-suite audit caught a real regression: adding automatic `entry_date` made older test
fixtures titled `08/11/2024` look newly created today. I fixed creation to recognize a dated
Journal title before falling back to the current local date. I did not change those tests. The
combined memory/stats retest then reported `4 passed in 0.38s`, and the full suite finished at
`57 passed in 6.55s`. The focused stats tests were `2 passed in 0.35s`; the production web build
also compiled and completed TypeScript successfully.

## 20:45 — Notes tags are visible and open the right Codex entry

The detector was already writing typed `codex_links` into note frontmatter, but those links stopped
at the API. Notes now read the active note's links and render them as the compact rounded chips from
the design reference: green for Character, amber for the other detected types, with `Type · Name`
on every chip. They refresh after autosave, clear when the project changes, and reload when another
note is selected.

Clicking a chip passes its stored type and `entry_id` through DraftShell to the existing Codex
panel. The panel opens that exact entry, using the same targeted-open path Cmd+K already uses,
instead of opening an unfiltered Codex list and making the writer search again.

The audit also found that auto-tagging rewrote frontmatter after `write_content` had calculated its
response hash. That stale hash could cause the editor's next save to report a false disk conflict.
The API now rereads the finished markdown and returns the real post-tag hash and metadata.

Focused proof: `3 passed in 0.22s`. The API test resolves every stored chip target through the
Codex entry endpoint and confirms the returned title matches the tag name; it also checks the
response hash against the final file. Full suite: `57 passed in 7.03s`. The production build and
TypeScript pass completed twice, including the post-audit state-clear fix.

## 21:30 — Skins and tray edge are real preferences

Onboarding was jumping straight from the AI choice into the tour. Design wants a skins
and tray-edge step in between, and Settings Appearance was still an empty card. I wired
both to the same vault settings keys.

New vaults default to daily skins off and tray on the left. Older settings files pick up
those defaults on read without rewriting the JSON until something saves. Tray edge is
validated to left or right; a bad value returns 400 instead of writing junk. Cmd+K can
turn skins on/off and flip the tray with the same permitted-settings path.

The shell now docks the tray on either edge in Draft and the module workspaces. When
skins are on, today's image comes from local `assets/skins/` when that folder has files;
otherwise the UI keeps the placeholder pattern so the preference still means something
on a clean checkout.

Focused proof: `5 passed` in `tests/test_appearance_settings.py`. Full suite: `62 passed
in 8.13s`. `npm run build` compiled and finished TypeScript cleanly.

## 21:45 — Per-entry Exclude from AI

Book-level Private Journal encryption was never going to cover the common case where a
single Notes or Journal entry should stay fully readable by me but invisible to Muse,
memory callbacks, Ask-your-vault, and auto-tag. The addendum from market research called
that out as a missing control, so I added it as its own frontmatter flag.

`exclude_from_ai` survives autosave instead of getting wiped when write_content rebuilds
meta. Journal memory skips excluded entries. Ask-your-vault search drops them for the AI
path while ordinary human search still finds them. Notes auto-tag refuses to run when the
flag is on. The UI toggle sits in the Notes/Journal chrome (and Zen Journal) and is
visually separate from the Private Book control.

Focused proof: `4 passed` in `tests/test_exclude_from_ai.py`, plus the Notes and memory
regressions. Full suite: `66 passed in 7.41s`. Production web build and TypeScript finished
clean.

## 21:55 — OpenClaw roles fail closed in the open

OpenClaw had a PATH health stub that always reported every role as false, even when the
binary existed, and Settings had nowhere to turn the three bridges on. Research, git, and
agentic are now independent settings, off by default, deep-merged so flipping one does not
wipe the others.

Health returns a per-role status with a visible reason. Missing binary, disabled role, and
unwired role execution all return structured `{ok:false, unavailable:true}` instead of
throwing or hanging. Settings shows those reasons next to each toggle and can probe a role
to print the same message.

Focused proof: `5 passed` in `tests/test_openclaw.py`. Full suite: `71 passed in 6.96s`.
